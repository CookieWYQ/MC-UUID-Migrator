# 迁移会做什么 + 备份还原

## 迁移三步

1. 自动备份所有涉及文件
2. 文件名改名：
   playerdata/A.dat → playerdata/B.dat
   （stats / advancements / maid_backups 同理）
3. 内容替换：文件里出现的 A 全部原位替换成 B

   - 文本文件（usercache 等）
   - gzip 压缩的 NBT（playerdata / level.dat / 女仆备份）
   - .mca 区块（世界里归 A 的女仆等实体）

## 特殊结构：UUID 前两位的「分桶目录」

有些模组会把玩家数据按 UUID 的**前两个字符**分成子目录，例如：

```
world/pokemon/pcstore/ab/abcdef01-2345-6789-abcd-ef0123456789.dat
                    ↑ 这一层就是分桶目录，由 UUID 前两位决定
```

这类模组（典型代表：方块宝可梦 Cobblemon）启动时会按**当前 UUID 的前两位**去找文件，
所以只改文件名是不够的，**必须连分桶目录一起搬**，否则模组会在新前缀目录下找不到旧数据，
表现为宝可梦、图鉴、PC 盒子、队伍全部变空。

本工具会自动识别这种「分桶目录 + UUID 文件名」的组合并一并迁移，无需额外设置。

方块宝可梦的常见数据位置（`<世界>` 指服务器或存档的世界文件夹）：

| 数据 | 路径 |
|---|---|
| 玩家通用数据 | `<世界>/cobblemonplayerdata/` |
| 图鉴 | `<世界>/pokedex/` |
| 招式学习器 | `<世界>/tm_moves/` |
| PC 盒子 | `<世界>/pokemon/pcstore/` |
| 队伍 | `<世界>/pokemon/playerpartystore/` |

宝可梦自身的「初训家（originalTrainer）」UUID、以及世界里已放出的宝可梦实体，
都由内容替换一并处理。

## 备份在哪

- UUID 迁移：`uuid_backup_时间戳_A_to_B`（备份所有涉及文件）
- Xaero 转移：`xaero_backup_时间戳_源_to_目标`（备份会被写入的目标路径点文件）
- Xaero 对齐：`xaero_backup_时间戳_容器_align_to_ID`（被改名文件 + 改名记录.txt）

说明：Xaero 地图区块只补缺失、绝不覆盖，所以不需要备份；
源容器的数据全程只读，也不会动。

## 怎么还原

把备份文件夹里的文件按相对路径拷回原位置即可。
Xaero 对齐的目录改名按 `改名记录.txt` 把右列改回左列。
